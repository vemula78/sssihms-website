NavBar (:547-604), styled from site.css .topbar/.navbar/.nav-logo.

Install via the Theme Builder portability import — see README "Installing header/footer into
the Theme Builder". Divi refuses classic editing of et_header_layout, and Library layouts made
through post-new.php never show in the "Add From Library" picker.

The nav uses the site's EXISTING WordPress menu (menu_id="2", "Primary Menu"), which already
carries the same top-level items and dropdowns the design's NAV array describes. Editing
Appearance → Menus therefore updates this header; no menu had to be rebuilt.

LAYOUT NOTES — measured on the live draft, 17-Sep-2026. Do not "tidy" these into one row.
- No "Get Care" CTA: removed at Praveen's request.
- The menu gets its OWN full-width row, under the logo. Putting the logo and menu on one line
  was tried and reverted, because it only fits on a wide monitor:
    * the 8 top-level items measure ~912px at 11px type;
    * at a 1440px viewport a 1_5/4_5 split gives the menu 944px, so it fits — but
    * Praveen's actual browser reports a ~995px CSS viewport (2x Retina display), where the
      1180px container shrinks to ~965px and a 4_5 column is only ~772px. The menu wrapped,
      dropping "Opportunities" onto a second line.
  Fitting one line at ~995px would need roughly 9px type, which is unreadable. A full-width
  row gives the menu the whole ~965px, which fits at 11px with room to spare.
- The trust line ("A Unit of Sri Sathya Sai Central Trust") sits in the TOP BAR, right-aligned,
  rather than under the logo, where it wrapped and added height.
- The logo MUST keep `max_height` — without it the image (2560px wide natively) stretches to
  fill its whole column.
- Never pass `logo="off"` to et_pb_menu. Divi treats it as a URL and renders a broken image
  (`src="http://off"`). Omit the attribute entirely.

Not reproduced from the React original: the mobile hamburger drawer (Divi's Menu module has its
own responsive drawer, used instead) and the logo's onError fallback to a text wordmark.
